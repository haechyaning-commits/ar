# 감사파일 개인정보 마스킹 자동화

감사실 감사파일(hwp/hwpx/pdf)에 포함된 개인정보를 수기로 하나씩 마스킹하는 작업을 줄이기 위한 도구입니다.
완전 자동화가 아니라 **"자동 탐지 + 사람의 최종 검토/승인"** 구조로 설계되어 있습니다 — 이름/주소 같은 항목은 자동 탐지가 100% 정확할 수 없다는 전제하에, 사람이 검토 단계에서 최종 확인합니다.

개인 프로젝트로 진행 중이며, 실제 감사파일은 아직 사용하지 않습니다 (자세한 내용은 설계서 2.1 참고).

## 현재 상태

**PDF 입력 기준 MVP 구현 및 end-to-end 검증 완료.**

- 아키텍처 설계는 v14까지 정리됨 (타당성 평가 포함)
- PDF 파일을 넣으면 탐지 → 검토 → 마스킹 → 자체검증 → 원본 자동 이동 + 최소 로그 기록까지 전체 파이프라인이 실제로 동작함 (더미 데이터로 검증)
- 마스킹본 저장 → 원본 이동 → 로그 기록을 하나의 원자적 트랜잭션으로 처리: 어느 단계든 실패하면 이미 반영된 부분을 되돌려 원본은 항상 원래 위치에 그대로 남음 (성공/자체검증 실패/커밋 중 실패 세 경로 모두 직접 재현해 검증함)
- `mvp/tests/`에 실제 Qt 클릭 이벤트 기반 UI 테스트 + 탐지/마스킹/파이프라인 스트레스 테스트(27개 시나리오, `bash mvp/tests/run_all.sh`)가 있고, 이 테스트로 발견한 문제들을 수정함:
  - 숨겨진 콘텐츠(주석/폼필드/첨부파일)가 경고만 되고 실제로는 제거되지 않던 문제 → 독립적으로 스캔해 실제로 마스킹하도록 수정
  - 리댁션이 다른 주석을 덮어 삭제할 때 그 주석의 원본(마스킹 전) 어피어런스 스트림이 가비지 컬렉션 없이는 파일 바이트에 그대로 남던 문제 → `garbage=4`로 저장 + 저장된 파일을 바이트 단위로 재검증하는 안전망 추가
  - 회전된 텍스트 마스킹 시 대체 텍스트가 원본 방향을 무시하고 중복 삽입되던 문제 → 방향 반영하도록 수정
  - 처리 원자성의 사전조건 실패(예: 워크스페이스 폴더 자리에 파일이 있음)가 트레이스백으로 그대로 노출되던 문제 → 깔끔한 실패 결과로 수정
- 그 밖에 개발 중 발견한 버그도 실제 재현 테스트로 확인 후 수정함 (예: 마스킹 텍스트 폰트 크기 축소, 전화번호/계좌번호 이중탐지, 이메일 1글자 로컬파트 미마스킹, 재검증 실패 로그에 개인정보 실값이 그대로 찍히던 문제 등)
- **아직 없는 것**: hwp/hwpx → PDF 변환(한글/Windows 환경 필요, 미착수), .exe 패키징, 요약리포트, 재실행 방지, OCG(선택적 콘텐츠 레이어)의 실제 스크러빙(존재 경고만 있음)

## MVP

PDF 입력만 지원하는 최소 동작 버전입니다 (hwp/hwpx 변환 어댑터는 범위 밖).

- [`mvp/detector.py`](mvp/detector.py) — 개인정보 탐지 엔진. 전화번호/이메일/계좌번호/주민등록번호(체크섬 검증)/여권번호는 정규식, 이름/주소는 사전+문맥규칙 기반
- [`mvp/masker.py`](mvp/masker.py) — 실제 리댁션(오버레이 아님, 회전된 텍스트도 방향 반영) + 항목별 부분/완전마스킹 + 저장 전 자체 재검증 + 저장된 파일 바이트 레벨 재검증 + 숨김 콘텐츠(주석/폼필드/첨부파일) 실제 스크러빙 + 메타데이터 제거
- [`mvp/review_ui.py`](mvp/review_ui.py) — 최소 검토 화면 (PySide6). 기본 전체 승인 상태에서 예외만 체크 해제
- [`mvp/pipeline.py`](mvp/pipeline.py) — 마스킹 저장 → 원본 자동 이동 → 로그 기록을 하나의 원자적 트랜잭션으로 묶는 오케스트레이션. 어느 단계든 실패하면 이미 반영된 부분을 되돌려 원본을 원래 위치로 복구
- [`mvp/audit_log.py`](mvp/audit_log.py) — 최소 감사 로그(CSV). 건수/유형 + 원본 SHA-256 해시만 기록, 개인정보 실값은 남기지 않음
- [`mvp/main.py`](mvp/main.py) — 위 모듈들을 잇는 진입점
- [`mvp/data/`](mvp/data/) — 성씨/제외어/행정구역 사전
- [`mvp/tests/`](mvp/tests/) — 실제 Qt 클릭 이벤트 기반 UI 테스트 + 탐지/마스킹/파이프라인 스트레스 테스트. `bash mvp/tests/run_all.sh`로 전체 실행(디스플레이 없는 환경은 자동으로 Xvfb 사용)

**실행 방법** (디스플레이가 있는 PC에서):
```
pip install pymupdf pyside6
python3 mvp/main.py 파일.pdf [작업폴더]
```
탐지된 항목을 보여주는 검토 창이 뜨고, 승인하면 작업폴더(생략 시 입력 파일과 같은 폴더) 아래에
`마스킹완료/`(마스킹된 PDF), `원본_보관/`(자동 이동된 원본), `로그/audit_log.csv`(처리 이력)가 생성됩니다.
자체 재검증을 통과하지 못하거나 원본 이동/로그 기록 중 하나라도 실패하면 아무것도 반영되지 않고
원본은 원래 위치에 그대로 남습니다.

## PoC (Proof of Concept)

MVP 이전에, 더미 데이터로 핵심 기술 전제("마스킹이 오버레이가 아니라 진짜로 지워지는가")만 좁게 검증했던 초기 스크립트입니다. 실제 감사파일은 사용하지 않습니다.

- [`poc/masking_poc_test.py`](poc/masking_poc_test.py) — 정규식 탐지, 실제 리댁션(오버레이 아님), 자체 재검증, 메타데이터 제거, 회전된 텍스트 실패 케이스 검증
- [`poc/masking_poc_partial.py`](poc/masking_poc_partial.py) — 부분마스킹(`홍길동` → `홍*동`)이 리댁션 + 텍스트 재삽입으로 정상 렌더링되는지 검증
