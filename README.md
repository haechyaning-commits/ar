# 감사파일 개인정보 마스킹 자동화

감사실 감사파일(hwp/hwpx/pdf)에 포함된 개인정보를 수기로 하나씩 마스킹하는 작업을 줄이기 위한 도구입니다.
완전 자동화가 아니라 **"자동 탐지 + 사람의 최종 검토/승인"** 구조로 설계되어 있습니다 — 이름/주소 같은 항목은 자동 탐지가 100% 정확할 수 없다는 전제하에, 사람이 검토 단계에서 최종 확인합니다.

개인 프로젝트로 진행 중이며, 실제 감사파일은 아직 사용하지 않습니다 (자세한 내용은 설계서 2.1 참고).

## 현재 상태

**PDF 입력 기준 MVP 구현 및 end-to-end 검증 완료 (검토 UI, 출력/로그/리포트, 배치 처리 포함 전체 파이프라인).**

- 아키텍처 설계는 v21까지 정리됨 (타당성 평가 + 미검증 항목 실측 보완 포함, 12.5절)
- PDF 파일을 넣으면 탐지 → 재실행 방지 확인(6.4) → 검토(6.2.3 확신도 기반 저신뢰 우선정렬/동일값 일괄처리/페이지 진행상태/수동 추가/문서유형 선택 포함) → 마스킹(위치 기반, 회전 텍스트 방향 반영) → 자체검증(**실패 시 검토 화면으로 복귀해 안 지워진 항목을 하이라이트하고 재시도**) → 재실행 방지 마커·원본 자동 이동·감사로그·요약리포트까지 전체 파이프라인이 실제로 동작함 (더미 데이터로 검증)
- 마스킹본 저장 → 마커 기록 → 원본 이동 → 로그·리포트 기록을 하나의 원자적 트랜잭션으로 처리: 어느 단계든 실패하면 이미 반영된 부분을 되돌려 원본은 항상 원래 위치에 그대로 남음 (성공/자체검증 실패/커밋 중 실패 세 경로 모두 직접 재현해 검증함)
- 여러 파일을 한 번에 넘기면 대기열로 순차 처리(`process_batch`) — 자동 일괄처리가 아니라 파일마다 검토 화면을 거치며, 한 파일이 실패/취소돼도 나머지는 계속 진행
- 카드번호 탐지 추가 (계좌번호만 있고 빠져있던 범위 항목), 계좌·카드번호는 완전/부분(끝 4자리 유지) 마스킹을 설정값 하나로 전환 가능(9번 표 "확정 대기" 항목 대응)
- 사전 자동 학습(6.2.1) — 검토자가 자동탐지 이름을 체크 해제하거나 수동으로 이름을 추가하는 행동을 조용히 누적해, 같은 단어가 3회 반복되면 확인 없이 성씨/제외어 사전에 반영하고 즉시 재적용(`detector.reload_dictionaries()` — 배치 처리 중 다음 파일부터 바로 반영). 검토 화면 상단에 최근 반영 내역을 되돌리기 버튼과 함께 보여줘 잘못 반영된 게 있으면 언제든 되돌릴 수 있음
- 문서 템플릿 지문 인식(6.2.2) — 검토자가 승인한 항목들의 라벨/상대좌표를 문서 레이아웃과 함께 조용히 지문으로 축적(`mvp/template_fingerprint.py`). 같은 양식(라벨 위치 기반 유사도로 판별)이 다시 들어오면, 이번엔 탐지가 놓친 위치(예: 성씨사전에 없는 이름)를 그룹 "템플릿후보"로 검토 목록에 되살려 제시. 사전 자동학습과 같은 결로 별도 확인 절차 없이 승인 행동만으로 누적됨
- 원본-마스킹본 비교 뷰(6.3.2, `mvp/compare_view.py`) — ① 승인 전: 검토 화면에서 "미리보기 비교" 버튼을 누르면 왼쪽 원본/오른쪽 시뮬레이션(체크된 항목을 화면에만 검은 사각형으로 표시, 파일은 안 건드림)을 모덜리스 창으로 나란히 보여주고 체크박스 토글마다 실시간 갱신. ② 승인 후: 처리 성공 직후 "원본과 결과물을 비교해서 확인하시겠습니까?"로 물어보고, 원하면 `원본_보관/`과 `마스킹완료/`의 실제 파일을 읽기 전용으로 나란히 열어줌
- 실사용자 편의 기능(6.3.6) — 항목마다 "🔍 확대" 버튼을 붙여 누르면 그 항목 주변만 고배율(화면 표시의 약 2.7배)로 다시 렌더링해 팝업으로 보여줌(숫자 오독 방지). "다음 미확정 항목" 버튼/단축키(Ctrl+J)는 확신도가 "높음"(정규식으로 이미 확실한 항목)이 아닌 것만 순서대로 포커스 이동
- hwp/hwpx → PDF 변환은 골격만 작성됨 (`mvp/hwp_converter.py`) — Windows + 한컴오피스 환경이 없어 이 세션에서는 실동작 검증도, 파이프라인 연결도 못함(스켈레톤만 존재, main.py는 아직 호출하지 않음)
- `mvp/tests/`에 실제 Qt 클릭 이벤트 기반 UI 테스트 + 탐지/마스킹/파이프라인/템플릿 지문 스트레스 테스트(`bash mvp/tests/run_all.sh`)가 있고, 이 테스트로 발견한 문제들을 수정함:
  - 숨겨진 콘텐츠(주석/폼필드/첨부파일)가 경고만 되고 실제로는 제거되지 않던 문제 → 독립적으로 스캔해 실제로 마스킹하도록 수정
  - 리댁션이 다른 주석을 덮어 삭제할 때 그 주석의 원본(마스킹 전) 어피어런스 스트림이 가비지 컬렉션 없이는 파일 바이트에 그대로 남던 문제 → `garbage=4`로 저장 + 저장된 파일을 바이트 단위로 재검증하는 안전망 추가
  - 회전된 텍스트 마스킹 시 대체 텍스트가 원본 방향을 무시하고 중복 삽입되던 문제 → 방향 반영하도록 수정
  - 처리 원자성의 사전조건 실패(예: 워크스페이스 폴더 자리에 파일이 있음)가 트레이스백으로 그대로 노출되던 문제 → 깔끔한 실패 결과로 수정
  - 라벨 뒤에 지역명만 단독으로 있는 경우(예: "주소: 서울")까지 주소로 오탐하던 문제 → 상세 주소 없이 지역명 하나뿐이면 제외하도록 수정 (`bash mvp/tests/run_all.sh`로 스크립트 모드 실행 시에만 드러남 — pytest는 `check()` 소프트 실패를 감지하지 못해 이 버그를 계속 놓쳤음)
- 그 밖에 개발 중 발견한 버그도 실제 재현 테스트로 확인 후 수정함 (예: 마스킹 텍스트 폰트 크기 축소, 전화번호/계좌번호 이중탐지, 이메일 1글자 로컬파트 미마스킹, 재검증 실패 로그에 개인정보 실값이 그대로 찍히던 문제 등)
- 이름/주소 탐지 정확도를 12개 시나리오 더미 코퍼스로 실측: **이름 precision 93%/recall 82%, 주소 precision 100%/recall 100%** (`mvp/evaluate_detection_accuracy.py`)
- Linux에서 PyInstaller 단일 실행파일 빌드를 실제로 수행해 패키징 메커니즘(의존성/데이터파일 번들링)을 검증함 — 단, 실제 배포 대상인 **Windows용 .exe는 미검증**
- 헤드리스(offscreen Qt) 환경에서 검토 UI를 포함한 전체 파이프라인 통합 테스트를 실행해 도구 자체의 처리 시간(5페이지·54건 기준 평균 0.1초 미만)을 실측함
- **아직 없는 것**: hwp/hwpx → PDF 변환 실동작 검증 및 파이프라인 연결(Windows+한컴오피스 필요), Windows용 .exe 실제 빌드, OCG(선택적 콘텐츠 레이어)의 실제 스크러빙(존재 경고만 있음), 실제 화면으로 클릭해보는 인터랙티브 테스트(이 개발 환경엔 디스플레이가 없어 헤드리스로만 검증함)

## MVP

PDF 입력만 지원하는 최소 동작 버전입니다 (hwp/hwpx 변환 어댑터는 골격만 있고 아직 연결 안 됨).

- [`mvp/detector.py`](mvp/detector.py) — 개인정보 탐지 엔진. 전화번호/이메일/계좌번호/카드번호/주민등록번호(체크섬 검증)/여권번호는 정규식, 이름/주소는 사전+문맥규칙 기반. 교차검증 규칙(6.2.3)으로 탐지 확신도 점수를 매기고, `reload_dictionaries()`로 사전 자동학습 결과를 즉시 재적용
- [`mvp/pdf_extract.py`](mvp/pdf_extract.py) — PDF에서 평문(탐지용)과 페이지/좌표 매핑(마스킹용)을 같은 방식으로 함께 추출하는 공용 모듈. 탐지와 마스킹이 같은 오프셋 기준을 쓰게 해서 위치가 어긋나지 않게 함(회전된 텍스트도 진행 방향 반영)
- [`mvp/masker.py`](mvp/masker.py) — 실제 리댁션(오버레이 아님, 회전된 텍스트도 방향 반영) + 항목별 부분/완전마스킹(계좌·카드는 완전/부분 전환 가능한 설정값) + 저장 전 자체 재검증 + 저장된 파일 바이트 레벨 재검증 + 숨김 콘텐츠(주석/폼필드/첨부파일) 실제 스크러빙 + 메타데이터 제거. 승인된 항목의 위치(좌표)만 정확히 마스킹 (문자열 값으로 페이지 전체를 재검색하지 않음)
- [`mvp/review_ui.py`](mvp/review_ui.py) — 검토 화면 (PySide6). 기본 전체 승인 상태에서 예외만 체크 해제, 저신뢰 항목 우선 정렬(6.3.5), 동일 값 일괄 처리(6.3.3), 페이지 단위 진행 상태 표시(6.3.4), 문서 유형 선택(6.6 파일명 규칙에 사용), 사전 자동학습 트리거(체크 해제/수동 추가), 자체검증 재시도 시 안 지워진 항목 하이라이트, 항목별 확대 보기·"다음 미확정 항목" 순회(6.3.6)
- [`mvp/page_viewer.py`](mvp/page_viewer.py) — 수동 추가 화면(6.3.1). PDF 페이지를 이미지로 렌더링해서 보여주고 드래그/클릭/텍스트 입력으로 자동탐지가 놓친 항목을 추가. 유형은 형식 기반 자동 추정(`detector.classify_value`), 틀리면 같은 위치를 다시 선택해 정정
- [`mvp/compare_view.py`](mvp/compare_view.py) — 원본-마스킹본 비교 뷰(6.3.2). ① 승인 전: 체크된 항목을 화면에만 검은 사각형으로 그려 시뮬레이션한 미리보기를 원본과 나란히 모덜리스로 보여주고 체크박스 토글마다 실시간 갱신(`PreviewCompareDialog`, 파일은 안 건드림). ② 승인 후: 저장된 원본/마스킹본 두 파일을 읽기 전용으로 나란히 열어주는 범용 뷰어(`SideBySidePdfDialog`, `open_result_comparison`)
- [`mvp/dictionary_learning.py`](mvp/dictionary_learning.py) — 사전 자동 학습(6.2.1). 체크 해제/수동 이름 추가를 후보로 누적, 3회 반복 시 조용히 사전에 반영·이력 기록. 검토 화면 상단에 최근 반영 내역 + 되돌리기 버튼 패널로 연결됨(`review_ui.py`, 창이 새로 뜰 때마다 최신 상태로 표시)
- [`mvp/template_fingerprint.py`](mvp/template_fingerprint.py) — 문서 템플릿 지문 인식(6.2.2). 승인된 항목의 라벨/상대좌표를 문서 레이아웃(라벨 위치 기반 앵커 집합)과 함께 조용히 축적, 같은 양식이 재입력되면(레이아웃 유사도 Jaccard로 판별) 이번엔 탐지가 놓친 위치를 그룹 "템플릿후보"로 검토 화면에 되살려 제시(`mvp/data/template_fingerprints.json`)
- [`mvp/hwp_converter.py`](mvp/hwp_converter.py) — hwp/hwpx → PDF 변환 어댑터 골격 (Windows + 한컴오피스 환경에서만 동작, 아직 main.py에서 호출 안 함, 실측 전)
- [`mvp/pipeline.py`](mvp/pipeline.py) — 마스킹 저장 → 재실행 방지 마커 기록 → 원본 자동 이동 → 감사로그·요약리포트 기록을 하나의 원자적 트랜잭션으로 묶는 오케스트레이션. 어느 단계든 실패하면 이미 반영된 부분을 되돌려 원본을 원래 위치로 복구
- [`mvp/output.py`](mvp/output.py) — 출력 계층 유틸리티: 파일명 규칙(`[문서유형]_[처리일자]_[일련번호].pdf`)/폴더 구조, 재실행 방지 판별(PDF 메타데이터 마커), 요약리포트 작성, 처리자 식별(저장된 이름 재사용 또는 최초 1회 확인)
- [`mvp/audit_log.py`](mvp/audit_log.py) — 감사 로그(CSV). 건수/유형 + 원본 SHA-256 해시 + 회전텍스트/숨김콘텐츠 경고 플래그를 기록, 개인정보 실값은 남기지 않음
- [`mvp/main.py`](mvp/main.py) — 위 모듈들을 잇는 진입점. `process_file()`(단일 파일, 자체검증 실패 시 재시도 루프 포함) + `process_batch()`(여러 파일 순차 처리)
- [`mvp/data/`](mvp/data/) — 성씨/제외어/행정구역 사전 (사용하면서 자동 학습으로 갱신됨)
- [`mvp/evaluate_detection_accuracy.py`](mvp/evaluate_detection_accuracy.py) — 이름/주소 탐지 정밀도·재현율 실측 스크립트 (더미 코퍼스 12개 시나리오)
- [`mvp/tests/`](mvp/tests/) — 실제 Qt 클릭 이벤트 기반 UI 테스트 + 탐지/마스킹/파이프라인 스트레스 테스트. `bash mvp/tests/run_all.sh`로 전체 실행(디스플레이 없는 환경은 자동으로 Xvfb 사용) — **pytest가 아니라 이 스크립트로 실행해야 실제 결과가 나옴** (각 파일의 `check()`는 실패해도 예외를 던지지 않아, pytest로 돌리면 내부 실패가 무시되고 통과로 보고됨)

**실행 방법** (디스플레이가 있는 PC에서):
```
pip install pymupdf pyside6
python3 mvp/main.py 파일1.pdf [파일2.pdf ...]
```
파일마다 탐지된 항목과 문서유형 선택을 보여주는 검토 창이 순서대로 뜨고(여러 파일을 넘기면 대기열), 승인하면
`마스킹완료/[문서유형]_[처리일자]_[일련번호].pdf`가 생성되고, 원본은 `원본_보관/`으로 자동 이동, `로그/`에
감사로그, `요약리포트/`에 처리 요약이 함께 생성됩니다. 결과는 입력 파일 위치와 무관하게 항상 프로그램(.exe/스크립트)
옆 한 곳에 모입니다(6.6). 자체 재검증에 실패하면(대화형 모드) 검토 화면으로 돌아가 안 지워진 항목을 표시하고
재시도할 수 있고, 마커 기록/원본 이동/로그·리포트 기록 중 하나라도 실패하면 아무것도 반영되지 않고 원본은 원래
위치에 그대로 남습니다.

**정확도 측정 재현**:
```
pip install pymupdf pyside6
cd mvp && python3 evaluate_detection_accuracy.py
```

**패키징 (Linux에서 검증됨, Windows는 별도 검증 필요)**:
```
pip install pyinstaller
cd mvp && pyinstaller --onefile --name MaskingTool --add-data "data:data" main.py
```
Windows에서는 `--add-data` 구분자가 `:`가 아닌 `;`입니다 (`--add-data "data;data"`).

## PoC (Proof of Concept)

MVP 이전에, 더미 데이터로 핵심 기술 전제("마스킹이 오버레이가 아니라 진짜로 지워지는가")만 좁게 검증했던 초기 스크립트입니다. 실제 감사파일은 사용하지 않습니다.

- [`poc/masking_poc_test.py`](poc/masking_poc_test.py) — 정규식 탐지, 실제 리댁션(오버레이 아님), 자체 재검증, 메타데이터 제거, 회전된 텍스트 실패 케이스 검증
- [`poc/masking_poc_partial.py`](poc/masking_poc_partial.py) — 부분마스킹(`홍길동` → `홍*동`)이 리댁션 + 텍스트 재삽입으로 정상 렌더링되는지 검증
